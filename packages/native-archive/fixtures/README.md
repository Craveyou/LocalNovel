# Upstream archive fixtures

These are unchanged uuencoded fixtures copied from the official libarchive
3.8.9 release tarball, under `libarchive/test/`. Source archive and its SHA-256
are recorded in ../README.md. The corresponding upstream test C files are
retained here as provenance and expected-content documentation, not compiled.
Redistribution is governed by ../COPYING and the copyright/license headers
of those upstream test files (2-clause BSD).

The Swift tests decode the .uu files directly without executing external tools.
These are genuine RAR archives, not ZIP archives renamed to CBR or fake magic
headers. Their payloads are upstream text/binary test data, **not a complete
JPEG/PNG comic validation corpus**. A separate original 24-PNG RAR4 solid
CBR now lives in contracts/fixtures/documents/comic-basic-rar4-solid.cbr;
see ../RAR4-SOLID.md. Full JPEG/method coverage, real-device performance and
Android ABI verification remain gaps.

Positive cases: RAR4 non-solid binary data; RAR5 stored, compressed, single-file
solid and multi-file solid. Negative cases: RAR4/RAR5 encryption, multi-volume,
hard links and symlinks. Synthetic ZIP/CBZ cases are generated by the Swift
tests, including a 1x1 PNG, CP437, Unicode path fields, CRC corruption, path
attacks, NFC collisions, store/deflate and resource-limit failures.

RAR4 filename regression checks also create in-memory derivatives of the
binary-data fixture: only the first name, header lengths/flags and header CRC
change. The original compressed payloads and body CRCs are preserved. These
checks cover ASCII, raw UTF-8, encoded Unicode/non-BMP, NFC read-back and unsafe
encoding/path rejection; they do not turn the text/binary corpus into image CBR.
