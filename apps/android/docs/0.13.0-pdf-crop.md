# Android PDF 显示裁边

日期：2026-10-24。用户授权在 Android 完成 PDF 裁边，本轮只修改 `apps/android`，保留工作区原有修改。开发版本名保持 0.12.0。

后续用户反馈裁边不能拖动、PDF 界面与当前 TXT 规范不一致及卡顿，修正见 [阅读界面与裁边交互修正](0.13.0-pdf-reader-ui.md)。下文保留首次实现记录；当前入口改为正文中间点按展开浮层菜单，滑块始终可用且拖动即启用，版本名沿用工作区当前 0.13.0。

## 使用与范围

PDF 解锁且首屏打开成功后，阅读器底部提供“PDF 裁边”：

- 默认关闭；开启后左右各默认 10%，独立调节 0–30%，步长 1%。调整立即生效。
- 开启后按裁后宽度适配视口，支持继续双指/双击缩放、平移和长按持续拖动选文复制。
- “恢复原页”立即关闭裁边、恢复左右各 10%，面板保持打开，方便直接比较。
- 所有 PDF 共用本次应用进程内的设置；关闭/重开书籍、切换 PDF 保留。应用进程重启后关闭并恢复 10%/10%。退出到后台不等于进程重启。
- 仅手动裁显示后的左右边缘；旋转页面按旋转后的左右处理。无 OCR 或自动内容检测，裁掉正文时需减小比例或恢复原页。

## 实现边界

`PdfCropSettings` 只保存不可变的内存值，不接入偏好、SQLite、书籍元数据或同步协议。`PdfCropControls` 提供开关、两个百分比滑块和实时标签。

`PdfPageView` 复用当前页已有位图，在统一的原页到屏幕变换后裁剪 Canvas；图片、搜索高亮、选文和锚点共用变换。缩放和平移不能重新露出已裁掉的边缘，隐藏边缘不能被点选。没有整书预处理、额外页面位图、裁后 PDF 或解密副本。

裁边调整、恢复原页和视口变化不发出阅读位置事件。当前可见的原页纵坐标尽可能保留，受页面/视口边界约束；书签、正式位置、同步位置和阅读时间不变。页面实际拖动仍按原页纵坐标提交。搜索仍检索原始全文，手动裁掉的命中可以通过恢复原页查看。
