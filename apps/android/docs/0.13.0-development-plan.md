# 0.13.0 开发实施计划（Android 先行）

编制日期：2026-10-21。状态：阶段功能已有实现及自动化验证；真机/性能和发布验收待完成，见 [验证记录](../../../docs/product/plans/0.13.0-validation.md)。

## 1. 依据与执行范围

- 版本范围以 [0.13.0 需求清单](../../../docs/product/plans/0.13.0.md)、[多格式阅读需求](../../../docs/product/multi-format-reading.md)、[Decision 0017](../../../docs/product/decisions/0017-multi-format-release-scope.md) 为准，具体业务遵守关联 Capability。
- 开发顺序：共同契约与样本 → Android PDF 完整流程 → Android EPUB 完整流程 → iOS 多格式实现 → Android/iOS 接续验收。
- 用户已明确授权 Android、iOS、API 和 Backend 一并完成；共享 Swift 保持无平台 UI。保留不创建分支、不 commit、不 push 的约束。
- 本地导入、阅读、搜索、书签、复制不依赖后端上线。同步客户端可以先使用契约夹具和可替换传输测试；真实 Backend 和跨端验收仍是版本交付条件。
- 开发与中途测试保持客户端版本名 **0.12.0**；当前 Android 基线为 build **80**。每次客户端构建通过现有脚本递增 build，不因阶段完成提前改为 0.13.0。
- 保留现有未提交修改；不创建 Git 分支，不 commit、不 push。发布、部署、签名与 tag 不在本计划执行授权内。

## 2. 实施前的需求与代码核对结果（基线快照）

| 现状 | 代码依据 | 对开发顺序的影响 |
|---|---|---|
| 文件选择器仅提供 `text/*`，导入后直接检测 TXT 编码；单批上限 20 本 | `MainActivity.pickTxtFile`、`BookImportController`、`BookImportPolicy` | 扩展格式识别和校验；新格式限额单独确定，不能直接沿用 TXT 上限 |
| `Book` 没有格式字段，阅读、搜索、书签都采用字节 offset | `Book`、`BookSearchController`、`Bookmark`、`CatalogController` | 先建立类型化定位，再接 PDF；不能把页码写入现有字节字段 |
| SQLite 当前为 Schema v2，正式进度、书签和远端缓存均只有 `offset_bytes` | `LocalDatabase`、`LocalProgressStore`、`RemoteProgressStore` | 需要无损迁移、格式及定位版本隔离；保留旧 TXT 数据与同步状态 |
| 阅读器与 TXT 分段缓存、分页、选文绑定 | `MainActivity.showReader`、`ReaderSegmentSource`、`ReaderPageTextView` | 为新格式提供独立阅读适配器，保留现有 TXT 路径；按接入需要提取公共边界 |
| 正式阅读提交和同步协调已有独立规则，但参数仍为字节 offset | `FormalReadingProgress`、`ReadingProgressRecorder`、`ReadingSyncPhase`、`ProgressSyncCoordinator` | 复用阅读前比较、真实位移时间及会话规则，扩展位置模型 |
| 同步请求/响应仍使用 TXT v1 字段 | `SyncModels`、`SyncApiClient`、现行 OpenAPI | 新格式需要独立可解释的协议；旧客户端继续读写 TXT v1 |
| Android 仍拒绝来源设备名超过 20 字符的进度响应 | `SyncApiClient.parseRemote` | 纳入同步兼容修复及回归，按现行契约对齐，不缩窄服务端合法名称 |
| Gradle 尚未引入 PDF/EPUB 引擎 | `app/build.gradle` | 首先验证渲染、解密、文本提取和坐标映射，不能只证明页面能显示 |

已有 Android TXT 书架手势、长按删除、进度反馈、持续拖动选文属于回归基线，不重复开发。iOS 交互已有实现，R013-06 以复核和修复实际缺口为主。

### P0：先确定后续实现依赖的事实

1. 建立有使用权限的测试样本清单，记录文件哈希、大小、格式特征、预期位置和能力。密码样本使用测试密码；不使用用户私人文件或真实凭据。
2. PDF 引擎验证覆盖：min SDK 23、目标 SDK 35、Java 17；文本/扫描 PDF、常见打开密码、页面渲染、文本与字符区域、旋转缩放坐标、提取权限、取消与资源释放。评估许可证、依赖维护、包体、内存和原生库兼容，再锁定依赖版本。
3. 设计 `BookFormat` 与 `DocumentLocator` 等类型边界（名称暂定），统一用于正式进度、书签、目录目标和搜索命中；搜索会话与选区仍为临时状态。
4. 明确 TXT 原字节 offset、PDF 页面/归一化页内锚点、EPUB 正文资源/内容锚点的编码、版本、规范化、比较、排序、百分比及失效行为。PDF 内部索引、对外页码和文档页标签分别映射；EPUB 锚点可跨平台解析，不能依赖屏幕页号或单一引擎内部对象。
5. 为阅读事件建立测试表：恢复、缩放、重排、搜索预览不更新时间；实际翻页/导航才提交。页内平移、内链接和脚注往返的边界先作出产品结论，再编码。
6. 形成同步协同方案：格式及定位版本、旧 v1 隔离、未知定位处理、远端缓存隔离、单书云端删除的兼容和并发顺序。具体路由/字段在契约评审中确定，本计划不预设已存在的新 API。

P0 输出包括支持/受限样本矩阵、技术验证记录、定位设计及迁移用例、协议协同清单。涉及共享 Contract 或 OpenAPI 的正式变更在相应范围落实后实施；本地工作可按已定稿的本地语义继续。

### P1：优先保护已有数据和 TXT 用户流程

1. 为 Book 增加格式语义；引入类型化位置和按格式分发的文档会话，TXT 接入保持现有字节定位及分页行为。
2. 按评审后的本地 Contract 扩展 SQLite，迁移现有 Schema v1/v2 升级链。保留书籍、原 offset、阅读时间、书签、目录、设置、凭据边界和同步状态；不清库重建，不补造阅读时间。
3. 统一位置校验与规范化；书签按同书规范化定位唯一；远端缓存按账号、文件身份、格式及定位版本隔离。未知位置保留原状态并给出失败结果。
4. 保留原文件 SHA-256 + fileSize 身份。导入使用临时文件、校验、文件发布和数据库提交的可恢复流程，明确跨文件系统/SQLite 的补偿与重启清理，不能假定二者共享事务。
5. 将缓存与正式数据分开；删书事务记录待删文件，提交后清理原文件应用副本和派生缓存，失败可重试，用户源文件不删除。

验收：迁移前后逐项核对 TXT 数据；注入迁移中断、磁盘不足和文件删除失败；重复启动无重复记录；未知文件/定位不静默变成 0%。

### P2：先交付能离线运行的 PDF 用户流程

1. 扩展系统文件选择与实际格式识别，检测基本结构；伪后缀、损坏文件、取消或失败不留下可点击坏书籍。验证有效但未解锁的 PDF 可以保留为“需要密码”，不伪造页数或进度。
2. 打开链路分为：识别/校验 → 需要密码/解锁 → 可定位 → 本地恢复 → 可选同步比较及用户选择 → 正式阅读。未解锁不能提前拉取比较、写阅读时间或上传。
3. 完成文本/扫描 PDF 原版阅读、前后页、指定页、缩放/适配、不同尺寸与旋转页面；菜单适配主题，文档及图片不强制反色。PDF 不显示无意义的字号/行距选项。
4. 密码错误可重试、取消返回原入口；关闭后重开重新输入，保留旧位置和时间。密码仅在会话内存使用，关闭/取消释放；不写数据库、日志、同步或持久化解密副本，敏感页面/索引不落入普通磁盘缓存。
5. 覆盖退出、切书、后台、重启和加载期间离开；已失效异步任务不得覆盖新书/新会话。

验收：普通、扫描和密码 PDF 均有可用样本；正确/错误/重试/取消/重开均可复现；损坏或不支持加密明确提示且保留已有数据；无后端可正常完成本地阅读。

### P3：完成 PDF 文本能力和书签

1. 将提取文本映射回原页与区域，处理断行和 Unicode，不将提取结果当作替代正文渲染。
2. 复用搜索共同规则：不区分大小写、不重叠、2–32 个扩展字素簇、每批 200 条可继续、用户主动回绕；命中按文档顺序定位，临时阅读不写正式进度或时间。
3. 按统一定位添加、列出、跳转、同位置判重和单条删除书签；缓存删除后仍能跳转；无效锚点不回退书首。
4. 实现允许提取文本的页内选取、调整、取消和主动复制，保留原文及换行，不附加书名/位置。缩放旋转后选区坐标准确，选文不误翻页、不更新正式进度。
5. 无文本层、禁止提取或引擎无法可靠提取时说明原因；扫描件仍可阅读、添加书签和同步位置，不执行 OCR。

### P4：同步闭环与 PDF 阶段验收

1. 扩展 Android 本地快照、远端缓存、传输解析与阅读前提示，使用类型化定位；界面显示双方可解释的进度，不以二进制文件大小伪造百分比。
2. 用可替换传输和契约夹具验证成功、失败、未知格式/版本、越界、不同文件、旧响应及在途请求，开发不依赖服务实时在线。
3. 协同交付 OpenAPI、API 文档、Backend PostgreSQL 迁移/校验/时间裁决、旧 TXT v1 隔离与单书删除回归；真实服务可用后执行双 Android 接续测试。该协同工作已由用户授权，并与双端接入一起实施。
4. 保留仅活动书上传、真实阅读时间优先、跳转先确认、接受远端保留远端时间、拒绝保留本地时间、离线退出不补传、恢复网络先比较的规则。
5. 单书云端删除与上传保持串行；成功后本次阅读会话持续暂停上传，刷新/网络恢复不得解除；退出重开后重新比较。云端删除不影响本地阅读。
6. 修复并覆盖合法长设备名称响应的兼容问题，避免新格式联调沿用现存缺陷。

没有真实 Backend 时可以完成本地功能与客户端测试，但 P4 同步验收保持待完成；依照需求顺序，不将其标记完成后直接进入 EPUB 实施。

### P5：PDF 验证后完成 EPUB

1. 先用支持样本验证 EPUB 引擎及资源/锚点互操作，再锁定依赖；采用 P0 确定的定位语义，不持久化排版页码。
2. 校验包结构、正文阅读顺序与资源路径；按出版物顺序跨章，优先有效内置目录，无目录仍可阅读，支持范围内文本和图片离线使用。
3. 字体/字号、行距、主题、方向或显示尺寸改变后恢复原内容位置，不因重排更新时间；章节和全书百分比遵守统一规则。
4. 完成内容锚点上的搜索、临时阅读、书签、页内选文复制和类型化同步，沿用 P3/P4 的共同规则。
5. 限制解包大小/数量/压缩膨胀，防止路径越界；不自动执行脚本或加载远端资源，外部链接由用户主动操作。缺资源、损坏、DRM 或未支持内容均有明确状态。

验收：文件名乱序不影响正文顺序；跨章/目录/组合字符/图片样本成功；重排、重启和清缓存后定位一致；TXT/PDF/EPUB 混合书库和双 Android 同步回归通过。

### P6/P7：跨端与版本收口

- R013-04/05：Android 验证后，iOS 按 PDF → EPUB 实施相同位置及业务语义，UI 和渲染可独立；共享 Swift 仅承载无 UI 的公共逻辑。
- R013-06：复核已有书架手势/长按删除、选文及进度隔离；保留两位小数双滚轮和“前往”，不改成 Android 滑块。已有代码先验收，有缺口再修复。
- 对同一原文件完成 Android ↔ iOS 双向接续，包含两端分别解锁密码 PDF、字号/屏幕尺寸不同的 EPUB、回读后较新时间胜出、接受/拒绝远端位置和异常恢复。
- 对应客户端全部需求与适当设备验收完成后再升级版本；清单准确记录各组件真实版本，Backend 单独确定组件版本。不得预建包含虚假 0.13.0 组件版本的发布清单。
- 同步更新已落实范围的 Capability、客户端实现记录、Matrix 和验收证据；自动化通过不等于真机或发布验收。

## 6. 测试、验证与证据

- **单元测试**：格式识别、定位序列化/校验/规范化、百分比边界、书签唯一性、搜索匹配/分批/回绕、正式阅读事件与同步裁决。
- **数据库/文件测试**：Schema 升级链、TXT 无损迁移、回滚/重复启动、空间不足、导入发布中断、取消、待删文件重试、缓存隔离和清理后恢复。
- **Android 交互测试**：真实导入到阅读再重开的闭环，密码五类操作，旋转缩放与选文，快速跳页/切书与异步返回顺序，主题及格式特有控件。
- **协议与集成测试**：旧 TXT v1 读写、新格式隔离、未知/越界定位、双设备竞争、时间优先、身份切换、删除与在途上传、离线及网络恢复。夹具结果与真实 Backend 集成结果分别记录。
- **设备与性能**：覆盖最低支持版本、目标 SDK 对应环境及代表性设备；对选定小/大样本记录导入、首屏、搜索、导航和峰值内存，测量后确定阈值，不预造性能数字。密码文档检查磁盘/日志无敏感派生内容。
- **TXT 回归**：导入/去重、书架手势与删除、目录、搜索、书签、选文、进度条、分页/偏好、正式时间与同步。

每个功能阶段运行 Android 针对性测试与 `./gradlew :app:testDebugUnitTest lintDebug`，使用根目录构建脚本生成测试包；普通代码变更按仓库要求运行 `make check`，Alpha 前运行 `make check-alpha` 及最终严格清单检查。全仓检查会验证后端、共享 Swift、Android 和 iOS；当前范围已获授权。

验收记录至少包含需求 ID、样本身份、设备/系统、测试步骤、预期/实际结果、失败处理、构建号与证据位置。未运行、受阻和通过分别标记。
