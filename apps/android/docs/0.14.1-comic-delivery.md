## 原生接入边界

Android 只修改 `apps/android`，直接消费 `packages/native-archive` 的固定源码，不改共享核心/Apple 目标。CMake 用实际 ANDROID_PLATFORM_LEVEL 校验最低 API；NDK 27.2.12479018 / CMake 3.22.1。三种 ABI 为 arm64-v8a、armeabi-v7a、x86_64，静态链接 C++ 运行库。原生核心在 Debug/Release 均使用 -O2 并保留相应符号，避免未优化的存储型 RAR4 处理路径在调试 APK 中产生秒级开销；不修改共享算法或缓冲语义。

NDK 旧工具链将 CMAKE_SYSTEM_VERSION 设为 1，Android 桥接对核心的版本检查提供实际 API 值。上游依赖的 android_lf.h 由 Android 接入层提供：1 GiB 原包上限下无需改写 32 位 off_t。UnRAR 不使用文件系统提取；已拒绝所有链接，min23 不可用的 symlink lutimes 路径显式返回 ENOTSUP，不回退到跟随链接写时间。

RAR4 采用严格 libarchive metadata-only 头校验与 UnRAR RAR_TEST 流式正文配对；EOF 必须为适配器约定的 1。所有隐藏项/非页面正文也会被校验；单次扫描按物理顺序解码全部图片验证，避免固实导入对每页重新解压前驱。随机读取只写入一个受限临时文件，不按包内路径落盘；临时空间、128 MiB 单项、4 GiB 展开、20,000 条目、64 MiB 文件名总量和 10,000 图片页受限。取消、CRC、加密、分卷、链接或异常条目均拒绝。全包校验不证明支持所有 RAR 算法。

完整 UnRAR 许可、Intel 声明和 libarchive COPYING 位于 app assets，并可在漫画设置的“开源许可”查看。`scripts/verify-native-apk.py` 检查真实 APK 中的声明、三 ABI LOAD/RELRO 16KiB 对齐、API23 强导入符号及 zipalign；NDK libc++ 的可选 weak memfd_create 单独记录，不能当成强依赖。

## 可复现测试

在 apps/android 中使用 Java 17：

```sh
./gradlew --offline --console=plain :app:testDebugUnitTest lintDebug :app:assembleDebug :app:assembleDebugAndroidTest
```

离线环境缺 UTP 附加输出插件时，直接安装上述两份 APK，并用 `adb shell am instrument` 运行相同 instrumentation 用例。原生夹具来自 contracts/fixtures/documents，不把测试原包打入应用 APK。

真实 Android HTTPS/PostgreSQL 测试：先安装 app 与测试 APK，在仓库根执行 `sh apps/android/scripts/test-comic-interop.sh`。该脚本消费现有公共测试服务，使用新建临时数据库/随机凭据/单次证书；仅对 emulator 开放，证书信任限定测试进程，退出清理端口转发与服务。测试四种同源原包、另一 Android 设备身份读取、回读较前页但时间更晚、异清单 422、正式会话接收、删除后不回传及 v1 数据隔离。它不启动或修改 iOS，不冒称双端接续。
