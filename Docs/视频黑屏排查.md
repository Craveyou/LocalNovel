# 视频黑屏排查手册（不改代码版）

> 目的：先用外部手段把「黑屏」定位到 **① 文件/编码不支持 ② 取流失败 ③ 渲染层没画面** 三者之一，
> 再决定要不要动代码。本手册只做取证，不修改 App 任何逻辑。
>
> 配套工具：`Tools/video_probe.sh`（一条命令给出「iOS 能不能播这个文件」的结论）

---

## 0. 一分钟定性：先看 4 个现象

打开出问题的那一集，观察这 4 点，能直接砍掉 2/3 的排查范围。

| 现象 | 说明 | 指向 |
| --- | --- | --- |
| 时长显示 `--:--`、进度条拖不动（灰） | `duration` 没读到 | 元数据层就没通：容器不支持 / 取流失败 / 文件残缺 |
| 时长正常，但画面全黑 | 索引读到了 | 视频轨解码失败，或渲染层没绑定 |
| **有声音、没画面** | 音频轨在播 | 视频轨编码不支持，或 AVPlayerLayer 没画面 |
| 点播放后几秒～几十秒才出画 | 正在缓冲 | 大文件 + 不支持 Range，或 moov 在文件尾 |
| 内联黑但全屏正常（或相反） | 同一 AVPlayer 两个宿主 | 纯渲染问题，与文件无关 |
| 点播放键图标变成暂停但没有画面 | 注意：图标只是本地状态，**不代表真在播** | 不能作为"播放成功"的证据 |

> 补充：播放键图标变暂停是 `LocalMediaPlayer.play()` 里直接 `isPlaying = true` 的结果，
> 与 `AVPlayerItem.status` 无关。这是当前**最容易误判**的地方。

## 1. 文件体检：先证明「这个文件 iOS 到底能不能播」

### 1.1 用脚本（推荐）

```bash
# 本地文件
./Tools/video_probe.sh /path/to/第12集.mkv

# NAS 上的文件（带 WebDAV 账号，脚本会同时验认证与 Range）
./Tools/video_probe.sh "http://192.168.1.10:5666/vol1/短剧/某剧/12.mp4" "用户名:密码"
```

输出示例（真实样本，mkv 容器）：

```
【容器】
  format : matroska,webm
  [FAIL] Matroska/WebM 容器：iOS 播放器完全不支持 → 必然黑屏
【视频轨】
  编码   : h264   [PASS] H.264 8bit，iOS 硬解支持
【结论】
 结论：发现 1 个阻断项 → 黑屏原因基本可确定
```

判定看三处：**容器 FAIL**（必黑）、**视频编码 FAIL**（必黑）、**数据完整性 FAIL**（文件没下完）。

### 1.2 在飞牛 NAS 上直接跑（不用把文件拉到电脑）

```bash
ssh 你的NAS
ffprobe -v error -show_entries format=format_name,duration:stream=codec_name,pix_fmt,profile \
        -of default=nw=1 "/vol1/短剧/某剧/12.mp4"
```

### 1.3 手工判读表（记不住脚本输出时用）

| 容器 / 编码 | iOS AVFoundation | 结果 |
| --- | --- | --- |
| mp4 / mov / m4v（H.264 yuv420p、HEVC Main/Main10） | 支持 | 正常 |
| **mkv / webm** | **不支持**（系统没有任何 mkv demuxer） | 必黑屏 |
| **avi / wmv / asf / flv / rmvb / vob / mpg / ts / m2ts** | **不支持** | 必黑屏 |
| mp4 里装 VP9 / AV1 | VP9 不支持；AV1 仅 A17 Pro / M3 以上 | 多数黑屏 |
| H.264 但 profile 是 High 4:2:2 / 4:4:4 / 10bit | 不支持 | 黑屏 |
| 音轨 DTS / TrueHD / Vorbis | 无解码器 | 常整条失败（黑屏 + 无声） |
| 音轨 AC3 / EAC3 | 支持 | 只有画面正常 |
| **HEVC 但封装标记是 `hev1`（不是 `hvc1`）** | Apple 只认 `hvc1` | **有声音、画面全黑**（可无损修复） |
| mp4 里装 MPEG-4 Part 2（`mp4v`，Xvid/DivX 同族） | 支持不稳定 | 多半黑屏 |
| moov 在文件尾（未 faststart） | 本地可播；HTTP 流播会先拉全片 | 长时间黑屏后出画 |

## 2. 三个对照实验（零工具，5 分钟）

这三个实验的价值：**只要系统级播放器也黑，就和 App 无关，直接判定文件问题。**

1. **Safari 直链**：NAS 上同一文件用 Safari 打开
   `http://192.168.1.10:5666/vol1/.../12.mp4`
   - Safari 能播 → 文件没问题，问题在 App 的取流/渲染
   - Safari 也黑 / 提示无法播放 → 文件或编码问题（Safari 与 App 用同一套 AVFoundation）
   - Safari 弹登录框 → 说明这条链路需要 Basic 认证，App 的认证头可能没送到（见第 3 节）

2. **「文件」App QuickLook**：把视频 AirDrop / 存到「文件」→ 点开预览
   - QuickLook 也黑 → 系统解不了这个文件

3. **VLC / nPlayer**：能播但前两个不能 → 更确认是「系统解码能力缺失」，不是文件损坏

| Safari | QuickLook | VLC | 结论 |
| --- | --- | --- | --- |
| 黑 | 黑 | 能播 | 容器/编码不被系统支持 → 转码或换片源 |
| 能播 | 能播 | — | 文件没问题 → 查 App 取流（第 3 节）与渲染（第 5 节） |
| 黑 | 黑 | 也黑 | 文件损坏/没下完 → 重拷 |

## 3. 传输层取证（只对 NAS / WebDAV 的视频有意义）

```bash
# 1) 看状态码、是否支持 Range、是否被重定向
curl -sS -o /dev/null -m 15 -r 0-1023 -u "用户名:密码" \
     -w "code=%{http_code} type=%{content_type} size=%{size_download} redirect=%{redirect_url}\n" \
     "http://192.168.1.10:5666/vol1/短剧/某剧/12.mp4"
```

| 结果 | 含义 | 后果 |
| --- | --- | --- |
| `206` + `video/mp4` | 正常 | 边下边播没问题 |
| `200`（不是 206） | 不支持 Range | AVPlayer 要整段下载，大文件长时间黑屏 |
| `301/302/307` + 有 redirect | 地址跳转 | **认证头在跳转后可能丢失** → 401 → 黑屏（见下方说明） |
| `401/403` | 认证失败 | 账号/密码错，或 header 没送到 |
| `404` | 路径不对 | 中文名 / 空格 / `#` 未编码 |

> **重点嫌疑**：`LocalMediaPlayer.swift:29` 与 `VideoMetadata.swift:44` 用的是
> `AVURLAsset(url:options:["AVURLAssetHTTPHeaderFieldsKey": ...])`。
> 这个 key 不是公开 API，Apple 从未文档化，**在服务器返回 302 跳转时不会带上它**，
> 也不参与 `AVAssetResourceLoader` 的重试链路。典型表现：列表里时长能读出来（PROPFIND 成功），
> 但一播放就黑屏 / 401。
>
> 判定方法：对比「`curl -I` 直接拿 206」与「App 内黑屏」。若 curl 正常、App 黑，
> 且响应头里有 `Location`，基本可以锁定是这条链路。

## 4. 运行时取证（不改代码）

### 4.1 Mac + Console.app（不需要 Xcode 工程）

1. iPhone 用 USB 连 Mac，打开「控制台 / Console.app」
2. 左侧选中 iPhone → 点「开始流式传输」
3. 搜索框依次搜：`AVPlayerItem`、`FigPlayer`、`-11800`、`-12847`、`401`

或命令行：

```bash
log stream --device-name "你的iPhone名称" --level debug \
  --predicate 'process == "mediaserverd" OR subsystem CONTAINS "AVFoundation" OR eventMessage CONTAINS "AVPlayerItem"'
```

然后复现黑屏，看这几类行：
- `AVPlayerItem failed` / `FigPlayerItemCreateFromURL failed`
- `HTTP 401/403/404`
- `-11828`（格式不认识）、`-11800`（未知错误，通常后面跟更具体的一条）

### 4.2 有 Xcode 时：断点 + 表达式（仍然不改代码）

在 `MediaAttachmentView` 的播放按钮动作上打断点，点播放后停下，在 LLDB 里逐条打印：

```
po controller.player.currentItem?.status.rawValue          // 0=unknown 1=ready 2=failed
po controller.player.currentItem?.error as Any
po controller.player.currentItem?.errorLog()?.events as Any  // 最关键：含 HTTP 码与底层错误
po controller.player.timeControlStatus.rawValue              // 0=paused 1=waiting 2=playing
po controller.player.reasonForWaitingToPlay?.rawValue as Any
po controller.player.currentItem?.presentationSize as Any    // 0x0 = 没解出视频轨
po controller.player.currentItem?.asset.tracks.count
```

判读：

| 观察 | 结论 |
| --- | --- |
| `status = 2` + `error` 有值 | 文件/取流失败，看 `errorLog` |
| `status = 1`，`presentationSize = 0x0` | 视频轨没解出来（容器/编码问题） |
| `status = 1`，`presentationSize` 正常，`timeControlStatus = 1` | 在等数据：网络/缓冲 |
| `status = 1`，`timeControlStatus = 2`，画面仍黑 | **渲染层问题**（见第 5 节） |

### 4.3 错误码速查

| 码 | 含义 | 常见原因 |
| --- | --- | --- |
| `-11800` | AVError.unknown | 兜底码，真正原因看 `errorLog` 或后一条 |
| `-11828` | 文件格式无法识别 | mkv/avi/rmvb 等容器 |
| `-11829` | 文件解析失败 | 索引损坏、文件截断 |
| `-11850` | 操作被中断 | 切后台、视图重建、播放器被释放 |
| `-11851` | 该时间点没有画面 | 拖到索引缺失的位置 |
| `-12909` | 解码器不可用 | 编码/profile 不支持（10bit、4:2:2、VP9、AV1 老机型） |
| `-1008 / -1009 / -1011` | 网络类 | 连不上、超时、HTTP 错误 |
| `-1100 / -1101` | 文件打不开 | 权限、路径、文件已删 |

> 以 `errorLog` 里打印的 `domain + code` 原文为准，上面的表只做方向判断。

## 5. 最后一刀：区分「解码失败」和「渲染失败」

前提：`status = .readyToPlay` 且 `presentationSize` 不是 0。此时黑屏只剩三种可能：

1. **内联黑、全屏正常** → `AVPlayerLayer` 绑定问题
   （`MediaAttachmentView.swift:63-89`；全屏时内联层被换成 `Rectangle`，退出后重建）
2. **全屏黑、内联正常** → `AVPlayerViewController` 宿主问题
   （`FullscreenVideoView.swift:114-137`）
3. **两边都黑，但有声音** → 视频轨解码失败（回到第 1 节，看编码）

另外注意比例兜底：`controller.videoAspect ?? 16/9`。读不到尺寸时会按 16:9 显示，
竖屏短剧会被压扁 + 上下黑边，**看起来像"黑屏"但其实是画面很小**——
把手机横过来或点进全屏就能区分。

## 7. 附件：当前代码里的 4 个「静默失败点」（本轮不改，只作为定位依据）

| 位置 | 现状 | 造成的结果 |
| --- | --- | --- |

## 8. 高嫌疑根因排序（基于代码与已知 iOS 能力）

1. **容器不在 AVFoundation 支持范围**（mkv/avi/wmv/flv/ts/rmvb/vob）——`MediaResolver.swift:17` 的白名单把它们都算作视频，能进播放器但解不出来。这是"个别视频黑屏、其它正常"的第一嫌疑。
2. **NAS 认证头靠未公开 key**，遇 302 丢失 → 401 黑屏（第 3 节）。
3. **moov 在文件尾 + 服务器不支持 Range** → 大文件长时间黑屏或永不启动。
4. **音轨 DTS/TrueHD** → 整条 item 失败，表现为黑屏 + 无声。
5. **渲染层绑定**（内联/全屏切换）→ 只有一边黑。
6. **文件本身没下完**（NAS 上传中断）→ 索引在但数据缺。

## 9. 专项：mp4 + 有声音 + 内联全屏都黑

这个组合已经把范围压到很窄了，逐条排除后只剩「视频轨解不出帧」：

| 已排除项 | 依据 |
| --- | --- |
| 容器不支持 | 后缀 mp4，且能读出时长、能播声音 → demuxer 工作正常 |
| 传输/认证失败 | 有声音说明数据在持续到达、播放器在推进 |
| 渲染层没绑定 | 内联（AVPlayerLayer）与全屏（AVPlayerViewController）是两个独立宿主，同时黑基本不可能 |
| 音轨问题 | 声音正常，说明音频解码链路完好 |

剩下的成因按概率排序：

| # | 成因 | 特征（ffprobe） | 处理 |
| --- | --- | --- | --- |
| 1 | **HEVC 标 `hev1`** | `codec_name=hevc` + `codec_tag_string=hev1` | **无损修**：`-c copy -tag:v hvc1`，几秒完成，画质音量不变 |
| 2 | AV1 | `codec_name=av1` / tag `av01` | 只有 A17 Pro、M3 及更新机型能硬解；其余需转码 |
| 3 | H.264 4:2:2 / 4:4:4 / 10bit | `profile=High 4:2:2` 等，`pix_fmt=yuv422p` | 重编码 H.264 8bit 4:2:0 |
| 4 | MPEG-4 Part 2 | `codec_name=mpeg4` + tag `mp4v` | 重编码 |
| 5 | 分辨率超上限 | `width>4096` 或 `height>4096` | 降分辨率重编码 |
| 6 | 畸形 mp4（缺 SPS/PPS） | 以上都正常但仍黑 | 只能重编码 |

### 零工具确认（不用电脑）

iPhone 上「文件」App → 我的 iPhone → LocalNovel（App 已开文件共享）→ 找到这个 mp4 →
**长按 → 快速查看**。QuickLook 与 App 用的是同一套 AVFoundation：

- QuickLook 也「有声音、黑画面」→ 确定是文件编码问题，与 App 无关
- QuickLook 能正常出画 → 回到第 5 节查渲染层（这种情况要改 App）

### 修复命令

```bash
# 情况 1：只改封装标记，无损（优先试这个）
ffmpeg -i 12.mp4 -map 0 -c copy -tag:v hvc1 -movflags +faststart 12-fixed.mp4

# 情况 2~6：统一转成 iOS 最稳的 H.264 8bit 4:2:0
ffmpeg -i 12.mp4 -c:v libx264 -profile:v high -pix_fmt yuv420p -crf 20 \
       -preset medium -c:a aac -b:a 128k -movflags +faststart 12-fixed.mp4
```

转完用原文件名覆盖回书库（或重新导入）即可，App 侧不需要任何改动。
