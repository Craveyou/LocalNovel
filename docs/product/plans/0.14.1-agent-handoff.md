## 并行开发与公共部分归属

用户已明确授权双端同批并行；2026-10-25 进一步允许在补齐漫画功能/界面的同时，推进第二批无 DRM MOBI/AZW/AZW3 的公共依赖及客户端功能，需要 iPhone 的验收集中后置。任何客户端都不以另一端整批完成或当前物理设备连接作为开发条件。真实持久化/联调仍等待相应公共规范/契约就绪。

| 资产 | 唯一修改负责方 | 交接要求 |
|---|---|---|
| 第一批排序/profile/定位与共享夹具 | iOS agent | 尽早发布规范输出/版本供两端同时消费；Android 复验并反馈差异 |
| OpenAPI、Backend、docs/API、PostgreSQL 迁移与测试 | iOS agent | 统一实现/验证，不交由 Android 另做一份；Backend 保持 PostgreSQL |
| 共享解析核心/依赖版本、许可、共享包 | iOS agent | 输出共同版本与构建约定；Android 在本端完成 JNI/Gradle 接入，iOS 完成 Swift/原生接入 |
| 公共存储/迁移语义与跨端数据 Contract | iOS agent | 定义兼容目标和共享向量；两端各自实现本地迁移，不替另一端改本地数据库代码 |
| 根脚本/CI、公共测试资产、产品/架构/矩阵文档 | iOS agent | 汇总双方证据后统一更新共享文件；不把单端结果当作双端通过 |
| Android 实现、本地 SQLite 迁移/桥接/构建/测试、Android 实现说明 | Android agent | 修改 apps/android 及 docs/product/clients/android.md；遵循 Android TXT 基线，消费公共契约 |
| iOS 实现、本地 SQLite 迁移/桥接/构建/测试、iOS 实现说明 | iOS agent | 修改 apps/ios、相关 AppleShared 及 iOS 实现说明；遵循 iOS TXT 基线，UI 不进入共享包 |
| 第二批解析版本、规范正文与定位向量 | iOS agent | 两端使用同源文件复验 textHash/UTF-16 坐标；通过后冻结，未冻结不得正式写入/上传 Kindle 位置 |
| 跨端双向接续与联合验收 | 双方提供本端证据，iOS agent 维护共同记录 | 明确客户端/服务 commit、构建、样本及 R014-15 的 TXT 对照；功能与模拟器测试随开发执行，需要 iPhone 的性能/压力/样本在全格式功能后联合补齐 |

Android 不修改公共契约/Backend/共享文档文件，发现缺口向 iOS agent 提交具体证据和所需字段/行为；由 iOS agent 修改、标识契约版本并通知 Android 更新消费。本地测试可使用隔离替身继续开发，但不得将替身当作真实服务验收，也不得临时定义线上兼容协议。两端 UI/本地代码各自维护，避免互相覆盖；工作目录/分支隔离由实际实施任务确定，本文不自动创建任务或发送消息。

## TXT 界面基线（R014-15）

所有新增/修改界面都沿用本端当前 TXT 阅读器的布局、菜单/弹窗、操作顺序、按钮形状/尺寸/圆角/间距/图标及状态、主题/字体/反馈、返回与取消逻辑。优先复用既有组件，不展示第三方默认阅读工具栏。两端分别固定 TXT 基线提交和截图，提供对照清单与 UI 回归证据；Android 与 iOS 不要求像素级相同。iOS 双滚轮及“前往”继续保留；漫画缩放等专属操作放入原控件体系，不因视觉一致而增加 OCR 或改变同步规则。

## Android 执行清单

- 第一批：修正内容识别和显式阅读分派；实现共享页序/页面清单；完成 CBZ 阅读链路后接 CBR 固实与非固实子集；采样/瓦片及可取消缓存；本地书签/恢复、SQLite 升级、同步会话/单书删除及旧格式回归。
- 对齐 Java 17 / min SDK 23，验证新 JNI 库支持目标 ABI、16 KiB 内存页和 Release 打包；不因引库自行升级工具链/最低系统。
- 与 iOS 第一批同时推进；消费 iOS 提供的公共页序/定位/样本，反馈 RAR 方法、依赖构建和坐标差异；提供本端验证包、哈希、内存/跳页和迁移/同步证据用于联合验收，不作为 iOS 开工门槛。
- 第二批不再等待第一批物理设备验收：消费公共解析器/规范与映射，再接排版/目录/搜索/复制/书签/同步，不用屏幕页号或转换 EPUB 顶替正式位置。非设备功能/安全回归继续随实现执行。
- 增加 R014-15 的 Android TXT 视觉/操作对照；按 R014 编号报告本端状态并更新本端说明，公共能力/矩阵由 iOS agent 根据证据统一修改。

## iOS 执行清单

- 与 Android 第一批同时推进独立文件入口、漫画模型/原生图像页面、SQLite 升级和现有同步会话集成；同时负责全部公共部分，尽早交付契约/夹具和可联调 Backend，使两端得到相同页序和 manifestHash。
- 对齐 Swift 6、现有 Xcode target 与真机/模拟器架构；AppleShared 只放无 UI 代码。沿用原生交互，保留既定 TXT 双滚轮，不复制 Android 布局。
- 不等待第一批物理设备验收，与 Android 并行推进第二批；先行产出公共核心/许可、正文规范/向量及 Backend 扩展，同期实现 iOS Kindle 桥接、排版/目录/搜索/复制/书签/同步。需要 iPhone 的性能/压力/样本集中到全格式功能后测试。
- Swift 文本索引转换为合同定义的 UTF-16 坐标，不能直接用 Character 数或 Swift String.Index 的距离充当 offset。
- 增加 R014-15 的 iOS TXT 视觉/操作对照；按 R014 编号报告本端及公共部分的独立证据，汇总双方结果更新共同文档，不把单端已验证当作双端已验证。

## 每批交接包必须包含

- 已完成的需求 ID、提交/工作区边界、真实版本/build、未实现与不支持的子集。
- 可再分发的原始样本及 SHA-256/大小、预期页序或正文、profile/hash/定位/进度向量。
- 固定依赖版本、编译方式、许可/分发核验、实际格式/压缩方法兼容范围。
- 旧数据库到新版本迁移、取消/空间不足/缓存清除、TXT/PDF/EPUB 回归与同步失败证据。
- 性能设备与构建模式、测量口径、峰值内存、首屏/远跳等结果；没有采样就记录缺口。
- 本端 TXT 基线提交、页面/按钮/菜单及操作对照、界面状态截图与回归结果；格式专属操作的必要差异。
- `implementation vs capability conflict` 如存在必须明确报告；不能迁就代码偷偷修改业务定义。

## 2026-10-25 Kindle 公共依赖交接（实际实现）

用户按 0020 允许第二批功能不等待物理设备验收。现已交付以下同源公共实现，不再沿用“没有解析器/样本/定位/API”的旧核对结论。完整证据及限制见 [Kindle 实施记录](0.14.1-kindle-implementation.md)，不是 G1/G2/G3 联合通过通知。

| 产物 | 实际路径 / 接入边界 | 宿主与验收状态 |
|---|---|---|
| 同源解析核心 / 许可 | `packages/kindle-core`，固定 foliate-js commit `78914aef4466eb960965702401634c2cb348e9b1` 的 MIT 非 DOM 解码部分；源码 SHA-256、许可及适配见包 README | Android 独占、禁网 WebView JS 宿主已接入，无新增 native JS 引擎；包内同源源码/许可核验通过 |
| 宿主合同 | `XLibKindle.parse({size,read(offset,count)},cancelled)`；同步 Uint8Array 精确读取、独占 VM、无网络；Apple JSC 桥接在 AppleShared/KindleDocument.swift | Android 按相同读取/解码/取消合同接入，不独立定义第二正文；不虚构 C ABI/JNI |
| 可再分发完整原包 | `contracts/fixtures/documents/kindle-*` 六包：MOBI6/PalmDOC/HUFF-CDIC/KF8/混合/长正文，原创 CC0；JSON 含 hash/size/模式/正文/映射 | 双端完整正文消费已验证，不以头部结构测试代替；更多出版商/设备压力样本后置 |
| 规范正文/资源/映射 | `docs/architecture/kindle-text-v1.md`、`core.js`、配套 JSON；Node/JSC/Android 一致、两端 DOM/图片/emoji/实际选区验证 | 六原包 textHash/UTF-16/目录/源跨度/封面同源通过；不等于完整设备/G2/G3 出口 |
| 定位、持久化、服务 | 严格 Kindle locator、`kindle-locators.json`、双端 SQLite v5 无损迁移、OpenAPI/Backend 与新增 PG005；不改 003/004 | 实际 Android↔iOS 五阶段通过，见联合记录；部署另行授权 |

支持子集：无 DRM 可重排 MOBI6/KF8，混合固定选 KF8，失败不回落旧正文；支持未压缩/PalmDOC/HUFF-CDIC 与 1252/UTF-8、离线 PNG/JPEG/GIF。明确拒绝 DRM、KFX/AZW4/Print Replica/固定版式及未知编码/压缩。限制包括原文件 1 GiB、实际选定解压正文累计 32 MiB、单次读取 16 MiB、深度/节点/映射/渲染和操作预算，详见规范。不是所有出版商变体或性能预算已达标的承诺。

参考输出一旦被正式保存不得原地改义；若发现规范差异，须修复宿主或提出新的 profile/迁移，不能偷偷重解释旧 offset。用户授权联调后已完成两个实际客户端的同源向量和[五阶段接续](0.14.1-kindle-cross-client-validation.md)，不再仅是“公共参考实现可接入”；功能证据与完整设备/发布验收仍须区分。

- 漫画四原包 Android↔iOS 同服务五阶段模拟器接续已通过，见[实际记录](0.14.1-comic-cross-client-validation.md)；更多非设备安全语料及完整异常状态按实际结果记录，不能用单元数量代替未测场景。

- iOS 功能/UI、常规非设备回归、核心安全及服务验证继续；结果持续更新实施记录。公共可接入、某端已实现、跨端已验收、真机已验收和服务已部署是不同结论。
