# 0.14.1 电子书格式扩展：需求分析与交付计划

状态：功能与界面优先推进，设备验收后置。2026-10-25 用户明确调整顺序：需要连接 iPhone 的性能/压力/样本测试，留到全格式功能完成后联合执行，不再阻塞 Kindle 开发；见 [Decision 0020](../decisions/0020-defer-device-validation.md)。漫画已有正式链路与四原包跨端模拟器证据，完整 G1/G3 尚未通过。进度见 [实施记录](0.14.1-comic-implementation.md)。本文件不表示整版完成，不改变版本源、发布清单或生产部署。

## 1. 目标与来源

用户确认需求目标调整为 **0.14.1**，新增电子书格式支持：**第一批 CBZ / CBR，第二批无 DRM 的 MOBI / AZW / AZW3**。Android、iOS 实现 agent 在同一批次内并行开发；所有需要新增/修改的公共部分由 iOS agent 负责。两批均属于 0.14.1 目标，不把只完成第一批描述为整个版本完成。

用户已明确确认版本、格式批次、双端并行、公共部分归属 iOS，以及全部界面遵循现有 TXT 阅读器规范。下表其余功能子集、限制及验收条件是设计基线，不冒充额外用户确认；需要扩大或缩减范围时先更新本需求及相关能力。不因另一客户端存在某个 UI 就自动要求复制。

| 项目 | 第一批：漫画包 | 第二批：Kindle 格式家族 |
|---|---|---|
| 产品能力 | [CAP-COMIC-READING](../capabilities/comic-reading.md) | [CAP-KINDLE-READING](../capabilities/kindle-reading.md) |
| 输入 | 无加密、单卷 CBZ（ZIP）和 CBR（RAR）；JPEG/PNG 页面 | 无 DRM、可重排 MOBI6、KF8/AZW3，含双格式混合文件；AZW 按内部内容识别 |
| 基本阅读 | 按确定页序阅读、上一/下一页、跳页、缩放、适宽/整页、重开恢复 | 按出版物顺序阅读文本/图片、跨内容单元导航、有效目录、字号/行距/主题、重排恢复 |
| 本地书签 | 添加、列表、定位、同位置判重和单条删除 | 同左，位置跟随正文内容，不跟随屏幕页号 |
| 搜索/复制 | 图片不提供正文搜索/复制，入口明确说明原因；不包含 OCR | 可提取正文沿用 CAP-SEARCH / CAP-TEXT-COPY；选文和搜索预览不写正式进度 |
| 可选进度同步 | 同一原始漫画包的页面/页内位置 | 同一原始电子书的规范内容位置 |
| 云端删除 | 只删除本书进度，成功后暂停本次会话上传 | 同左 |

## 2. 能力分类

| 变化 | 分类 | 处理 |
|---|---|---|
| 漫画包离线阅读 | B. New Product Capability | 新建 active CAP-COMIC-READING；CBZ/CBR 共用一个用户能力 |
| 无 DRM Kindle 电子书阅读 | B. New Product Capability | 新建 active CAP-KINDLE-READING；不按每个后缀重复建能力 |
| 导入、书库、恢复、目录、书签、搜索 | A. Existing Product Capability | 扩展已有能力的格式覆盖，保留现有规则 |
| 复制、进度同步、单书云端删除 | D. Shared Optional Capability | 复用既有定义；本版本按格式提供适用范围，不增加书签云同步 |
| 解包、图像解码、格式解析、缓存、SQLite 迁移 | F. Implementation Detail | 只进入架构与客户端实现说明 |
| 界面、系统文件选择、手势/导航 | F. Implementation Detail | 遵循本端现有 TXT 阅读器规范，不据此新增 Client-specific Feature |

没有从单端偶然实现中抽象新能力，因此本轮不新增 candidate；既有 CAP-AUTO-PAGING 保持 candidate，不自动扩展到新格式。

## 3. 功能需求与验收

以下为需求基线，逐项实现状态另见实施记录。需求 ID 在实现、测试和验收记录中保持稳定；双端分别记录状态，不以一端完成推断另一端完成。

| ID | 批次 | 需求与最低验收 |
|---|---|---|
| R014-01 | 共同准备 | 文件内容识别：区分 EPUB / CBZ / 普通 ZIP、RAR / CBR、MOBI6 / KF8 / 非支持内容；大小写后缀、错误后缀、伪装、未知类型不得落入 TXT 或 PDF 默认分支 |
| R014-02 | 共同准备 | 保留原文件，完整副本验证后才发布书库记录；失败/取消/空间不足不留半本书、不修改旧书；相同字节改名不改变同步身份 |
| R014-03 | 第一批 | CBZ 页序跨端确定；含子目录、1/2/10、补零、大小写、非 ASCII、隐藏项及重复路径夹具；不按压缩包物理顺序排列 |
| R014-04 | 第一批 | CBR：RAR4/RAR5 的已验证单卷无加密子集，含非固实与固实样本；随机跳页、取消和重开可用；不支持的算法明确提示，不冒充完整 RAR 兼容 |
| R014-05 | 第一批 | 漫画单页阅读、缩放、适宽/整页、长图页内导航、首尾和跳页边界；保留原图颜色，不因应用深色主题反色；不自动拆分跨页图 |
| R014-06 | 第一批 | 页数/页码、正式进度、本地恢复和书签一致；缩放不制造阅读事件；缓存清除、旋转、重启仍定位同一页面/内容锚点 |
| R014-07 | 第一批 | 漫画无正文搜索/复制，明确提示“图片漫画暂不支持正文搜索/复制”；页码导航不伪称文本搜索；不运行 OCR |
| R014-08 | 第二批 | 无 DRM MOBI6、KF8/AZW3 解析；混合文件确定选用 KF8，不因一端失败静默退为另一正文；AZW 后缀不是 DRM 或格式判定依据 |
| R014-09 | 第二批 | 文本、图片、有效目录和内部导航，缺目录仍可顺序阅读；字体/字号/行距/主题变更和视口变化保留内容位置；外部资源不自动联网 |
| R014-10 | 第二批 | 正文规范、搜索和复制共用内容坐标；沿用大小写不敏感、不重叠、2–32 用户感知字符、200 条分批、主动回绕；临时预览/选区不改正式位置/时间 |
| R014-11 | 第二批 | 内容书签添加/去重/单条删除、跳转及本地重开恢复；引擎输出、原始文本与显示文本的映射通过共享夹具证明 |
| R014-12 | 各批依赖 | 新格式进度契约及 Backend：先完成契约/双端编解码/服务验证再联调上传；时间优先、阅读前比较与双方百分比提示、只上传活动书、离线结束不补传、单书删除暂停均不变 |
| R014-13 | 各批依赖 | SQLite 无损迁移、未知定位保留、原文件缺失保护、缓存可重建；TXT/PDF/EPUB 旧位置、书签、设置、凭据和 v1/v2 同步不回退 |
| R014-14 | 各批验收 | 大包、多图、大图、长正文、搜索取消、快速切书、后台/重开、固实跳页、磁盘满、恶意路径和坏文件；记录真机峰值内存、首屏和跳转性能，不能以“能打开”结案 |
| R014-15 | 两批共同 | 所有新增/修改界面的布局、操作逻辑、按钮样式、菜单/弹窗、主题和反馈遵循本端现有 TXT 阅读器；逐项对照正常/禁用/加载/错误状态，保留 iOS 双滚轮等已有平台决定 |

### 界面与交互规范（R014-15）

- Android 对照当前 Android TXT 阅读器，iOS 对照当前 iOS TXT 阅读器；同一客户端的不同格式不能另起一套界面规范，也不要求两端像素级复制。
- 范围覆盖书架/导入、阅读页、上下菜单、目录/页面导航、搜索、书签、进度选择、设置、同步提示、错误/加载/空状态及删除确认；保持既有入口、菜单显隐、返回/取消/确认顺序和手势优先级。
- 按钮沿用既有组件或样式：形状、尺寸、圆角、间距、图标/文字、主次操作、按下/禁用/选中状态；字体、颜色、弹窗、浅深色主题和点击区域也沿用现行规范。不得直接暴露解析/预览库默认工具栏作为第二套操作界面。
- 复用本端 TXT 的进度选择交互，尤其保留 iOS 双滚轮及“前往”；映射到新格式的页面或内容位置，不把 TXT 字节位置硬套给新格式。
- 漫画缩放/适宽等格式专属操作在现有菜单/控件体系内增加；无正文搜索/复制仍按能力范围说明不可用，不因界面一致而虚构 OCR 或可复制文本。
- 各端在实施时记录所采用 TXT 基线的提交及对应页面截图/组件，使用同一基线进行视觉和操作回归。确需突破既有规范的交互先记录差异并提出产品判断，不自行改造整套 TXT 规范。

### 共同业务约束

- 离线阅读不依赖服务器转换；Backend 不接收或解析原书。
- 书籍身份始终为原始字节 SHA-256 + fileSize。重打包/转换生成的相同内容不自动视为同一书。
- 先完成解析、有效本地恢复、阅读前比较和用户选择，再进入正式阅读；导入、打开、解包、缓存重建、缩放、重排不刷新阅读时间。
- 图片漫画的正式位移为翻页、跳页及实际页内纵向移动；Kindle 为实际内容锚点移动。接受远端保留其时间，原地操作不制造时间。
- 书签仅本地保存；同步不上传原文件、正文、书名、文件名/路径、图片、目录、书签、搜索词/结果或阅读偏好。
- 封面采用确定的第一页或可用出版物封面；封面为可重建缓存。元数据缺失不影响阅读，用户编辑的书名/作者优先于再次提取。

## 4. 明确不纳入 0.14.1 的范围

- DOC/DOCX/RTF、KFX、AZW4/Print Replica、固定版式 Kindle、音视频和交互脚本。
- DRM 解锁、账号绑定或从 Kindle 商店拉书；带 DRM 文件明确说明原因，不弹普通密码框误导用户。
- CBZ/CBR 加密包、分卷包、嵌套压缩包阅读；SFX、自解压或外部命令调用。
- OCR、图片文字选择/复制、漫画编辑、自动裁白边、自动拼双页、ComicInfo 编辑/重排序、漫画自动识别阅读方向。
- 新格式自动翻页、书库/正文/书签云同步及服务端转换。

JPEG/PNG 是首期共同页面子集。包内存在其他已识别图片格式时明确提示不支持，不能静默跳过导致页数变化。密码包等排除项仅表示 0.14.1 子集，不把整个能力或其他客户端标成 unsupported。

## 5. 实施顺序与双端分工

本版本采用双端并行交付，2026-10-25 按用户最新指令调整为：**漫画功能/界面补齐及模拟器回归 → Kindle 公共依赖与双端功能并行实现 → 全格式功能/界面及契约回归 → 集中执行真机性能、设备压力/样本及整体验收**。其中漫画非设备待办与 Kindle 公共准备可并行；完整 G1 的物理设备证据不再是第二批开工前提。CBZ/CBR 两者均保留，延后的设备测试仍是整版交付必需项，不等于免测。客户端之间不设“一端完成另一端才能开始”的门槛。

两端可同时推进本地导入、解析 POC、界面、渲染、迁移及测试，不等待另一端整批完成。共同定位/profile/夹具由 iOS agent 尽早形成可消费基线；依赖未就绪时，Android 继续不受影响的客户端工作，可使用隔离测试替身，不自行另定线上协议或第二套正文真值。正式持久化和跨端同步仍须先通过共同契约校验，这是真实数据依赖，不是双端串行开发要求。

所有公共新增/修改统一由 **iOS agent** 负责：Backend、OpenAPI/API、PostgreSQL 迁移、跨端数据与定位 Contract、规范正文/排序规则、共享夹具、公共解析核心/版本与许可核验、共享包、根脚本/CI 和共同产品/架构文档。Android agent 负责 Android 客户端及其本地 SQLite 迁移、平台桥接/构建配置、测试与本端实现说明，消费并复验公共产物；公共问题交给 iOS agent 修正，不抢写公共文件。iOS agent 同时负责 iOS 客户端实现。详见 [agent 实现交接](0.14.1-agent-handoff.md)。

### 当前执行队列

1. 漫画功能/界面：已有加载/错误/禁用、书签、预览/返回、云端操作和 TXT 基线回归，四原包实际双向接续通过；保留方法/样本兼容限制。
2. Kindle 公共依赖：MIT 同源核心/许可、双端宿主、六原包与规范正文/UTF-16 映射已交付并复验，不再列待解析器。
3. Kindle 客户端及服务：两端导入/阅读/重排/目录、搜索/复制、书签/恢复、v5 存储与 OpenAPI/Backend/PG005 已实现；六原包真实五阶段接续通过，见[联合记录](0.14.1-kindle-cross-client-validation.md)。
4. 非真机回归：共享32项、核心7项、Backend88项含真实PG、iOS135项普通单元及Kindle UI2项、既有/漫画UI分组、Android293单元及模拟器流程已有通过证据；最终串行 `make check` 通过。失败修复链保留，未改号或伪造发布清单。
5. 设备联合验收：iPhone 可连接后一次编排漫画和 Kindle 等格式的真机内存/首屏/跳转/搜索与压力/样本、文件提供商和实际磁盘环境测试。没有结果前标记待验收，不标 done。

不需要连接 iPhone 的安全反例、坏文件、取消/限额、迁移与契约测试仍随实现执行。不得因后置性能测试而启用会损坏原书/旧位置的流程。

0.14.1 是修订后的需求/交付目标，替代原 0.14.0 方案；R014-01～14 保持稳定，新增 R014-15。本次不提前升级客户端，不回滚当前 0.13 开发状态，也不创建含虚假完成信息的 release 清单。此前“开发使用 0.12.0”的规则属于 0.13，不自动当作 0.14.1 的开发版本决定；实施时以实际版本源和完成的上一版本为基线，遵守根 AGENTS 的显式 VERSION / build 规则。发布、部署、tag、push 另行授权。
