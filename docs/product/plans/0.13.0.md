# 0.13.0 开发目标与需求范围

状态：主要功能已有实现、模拟器/服务集成验证及首轮大文档模拟性能测量；静态核对发现的 iOS 搜索边界缺口 I01/I02 已按原规则补齐，见 [搜索补齐记录](0.13.0-ios-search-completion.md)。iOS 已追加真机普通单元、UI、大文档 Release 测量和连续切书证据。复杂真实文件、低端设备、完整内存/性能预算、已发现热点的后续优化与版本发布验收仍待完成。用户确认当前讨论的需求统一纳入 0.13.0；Android/iOS 在开发和测试期间继续使用 0.12.0，完成对应需求并验收后才升级为 0.13.0。

本计划归集交付范围，不替代 Capability、API 或本地存储 Contract；需求业务定义仍以原文件为准。历史发布不重写，本计划不放入实际产品发布记录目录。

## 版本规则

| 阶段 | 客户端版本名 | 清单与检查 |
|---|---|---|
| 开发与中途测试 | Android versionName / iOS MARKETING_VERSION 均保持 0.12.0 | 使用 [0.12.0 draft](../../../releases/0.12.0.yaml)；默认 make check / check-alpha 选择此清单 |
| 客户端对应需求完成且验收通过 | 完成的客户端升级为 0.13.0；不得因单项任务完成就提前升级 | 更新对应客户端版本源、建立/更新 0.13.0 draft，并使清单准确记录各组件实际版本；仍在开发的客户端继续 0.12.0 |
| 版本整体验收完成 | 目标客户端对应范围均为 0.13.0 | 汇总最终 build 与范围，执行 Alpha 和严格发布清单检查；发布另行批准 |

build 号继续在每次客户端构建时递增，不随版本名重置。普通构建不传新的 VERSION，不隐式升级版本名。0.12.0 清单是开发检查快照，不声称已发布；构建中 build 号允许前进，正式发布检查仍要求最终 build 与清单一致。Backend 当前组件版本仍为 0.10.0；已确认多格式同步需要后端协议与 PostgreSQL 存储支持，实施时单独确定后端组件版本，不随移动端统一改号。服务与协议扩展已在开发工作区实现，Backend 组件版本仍保持 0.10.0，尚未部署。

当前不创建含虚假 0.13.0 组件版本的发布清单；在对应客户端完成后才建立准确的 0.13.0 draft。0.11.0 历史草稿及 0.10.0 强制迁移基线保留。现行签名、发布、tag、push、部署审批边界不受本计划改变。

## 待决项与交付顺序

[多格式需求中的实施前待确认表](../multi-format-reading.md#实施前需要确认) 是本版本范围讨论入口。每项在实施前确定纳入/后续评估及验收边界；未经决定不得偷偷删项，也不得把整类高级格式功能标成已承诺实现。正文复制根据明确交付承诺升为 active，理由见 [Decision 0017](../decisions/0017-multi-format-release-scope.md)；自动翻页仍为 candidate，新客户端或强认证等长期问题不由本次决定隐式扩展。

1. 首个格式已定为 PDF；先固化兼容样本、本地类型化位置/迁移 Contract 与多格式同步协议及旧客户端兼容策略。
2. Android 先 PDF（含密码、搜索、书签、复制、同步）完整验证，再 EPUB；TXT 行为不回退，不用现有字节同步接口伪装新格式定位。Backend 保持 PostgreSQL，协议与实现协同更新。
3. Android 验证完成后推进 iOS 多格式阅读；既有 iOS 交互可以独立复核，不影响该依赖顺序。
4. 各客户端全部对应范围完成后，按版本规则升级；未决范围必须有明确结论，不能以代码能编译替代需求完成。

## 完成与版本升级条件

- 本版本逐项需求有实现证据和验收结果，相关 Capability、Client Implementation 与 Matrix 按事实更新。
- PDF/EPUB 的支持子集、尚不覆盖的功能和错误状态明确；用户待决项已得到结论。
- TXT 数据、正式进度与同步规则不回退；SQLite/PostgreSQL 迁移和协议兼容通过验证，旧 v1 客户端不读取不可解释的新格式定位；密码不持久化或上传。
- PDF/EPUB 搜索、书签、复制与双端进度接续有成功和失败证据，密码/无文本层等受限状态明确；仅当前活动书上传及单书删除暂停规则不变。
- 各端自动测试与适当设备验收完成；make check 通过。升级版本后重新对齐清单与 build，并在 Alpha 准备前执行 make check-alpha。
- 版本名由 0.12.0 改为 0.13.0 是上述完成后的步骤，本次文档与检查修复不提前改名。发布记录仅在实际发布且经核实后补写。
