# 0.13.0 Android / iOS 功能完成与补齐清单

核对日期：2026-10-23。初次静态核对依据 [版本需求](0.13.0.md)、[多格式范围](../multi-format-reading.md)、提交 `163eae3`、当时未提交的双端修改、自动化源码及已有本机结果。后续按用户要求补齐 iOS I01/I02，新增结果见 [iOS 搜索补齐记录](0.13.0-ios-search-completion.md)；其他“已有验证”仍引用原记录，不代表本轮再次验收。

## 当前结论

- 初次静态核对两端均为 **0.12.0 build 86**；后续 build 以源码及各补齐记录为准。0.13.0 是交付目标，尚未升级或发布。Android/iOS 已有 TXT、PDF、EPUB 的主要业务流程，不能再把 PDF/EPUB 整体列为“待开发”。
- Android：未发现已承诺主要功能完全缺少入口；主要剩余为千页 PDF 搜索性能、兼容样本和代表性真机验收。
- iOS：主要入口和真机证据均已有；静态核对发现的两项搜索边界缺口 I01/I02 已按既有规则补齐，CAP-SEARCH 恢复 done。I03–I05 性能与验收边界仍保留。
- 两端共同：复杂真实文件、完整内存口径、性能预算与最终 Alpha/发布验收仍未收口。已有本地真实服务互操作，不等于新 v2 服务已经部署上线。
- 平台手势、控件和新增显示交互不自动传播；未承诺的 OCR、批注、DRM 等不作为本版本欠账。

## iOS 待办

### I01：PDF 默认搜索未使用当前页内位置（已修复）

分类：A. Existing Product Capability，**implementation vs capability conflict**，按已确认规则修复，不需要新产品能力或默认改写规则。

- 共同定义是从当前阅读位置向后查找，回绕只覆盖书首到固定原起点。
- 原问题：[DocumentReaderModel.search](../../../apps/ios/XLibReader/Documents/DocumentReaderModel.swift) 曾仅为 EPUB 设置正文 offset，PDF 只保留页号、未使用 `y`。滚到页面下半部时，上半部命中也会进入首段结果。
- 当前实现：按原始 crop box 与 0/90/180/270° 显示方向，将页内 `y` 映射到 PDFKit 文本坐标；保留与视口顶边相交的文字行。缓存未裁剪原框，不使用缩放后尺寸；查询创建时固定原起点，临时预览不重置游标。
- 补齐要求：PDF 页内视觉位置映射到搜索文本坐标，固定原起点；前半页命中仅在用户回绕后出现。覆盖旋转、缩放/裁边和分页后当前位置，确保不改正式进度/时间。
- 新增覆盖四种旋转、裁边/缩放、当前页内起搜、251 条结果续查与回绕、临时预览后的固定边界及正式时间隔离。设备结果见 [搜索补齐记录](0.13.0-ios-search-completion.md)。

### I02：从书首搜完仍显示不必要的回绕（已修复）

分类：A. Existing Product Capability，**implementation vs capability conflict**，较 I01 优先级低，但应在本版本修正。

- 原问题：[搜索面板](../../../apps/ios/XLibReader/Documents/DocumentReaderView.swift) 未判断原起点是否书首，完整搜完仍提供空范围回绕。
- 当前实现：`searchCanWrap` 同时要求已搜完后半段、尚未回绕、原起点之前存在文本范围；模型也拒绝无效回绕调用，不仅隐藏按钮。书首起搜完成直接显示“已完成一轮搜索”。
- 补齐要求：只有原起点非书首、尚未回绕且已完成后半段时才提供回绕；书首起搜完成后直接显示结束。继续满足“200 条是批大小而非总上限”。
- 新增 PDF/EPUB 单元与真实界面回归，见 [搜索补齐记录](0.13.0-ios-search-completion.md)；TXT 原有搜索器未修改。

### I03–I05：性能与验收

| ID | 类别 / 优先级 | 当前问题 | 完成标准 |
|---|---|---|---|
| I03 | EPUB 性能优化 / 优先 | iPhone 超长章首次打开中位 **2301.2 ms**，首次定位最大约 **1695.8 ms**；缓存后中位约 11 ms 不代表首次体验 | 明确打开与首次导航预算，复核首次布局/文本定位；有改善证据或接受现状的产品结论 |
| I04 | 内存验收 / 发布前 | 千页 PDF 真机应用采样峰值约 **511.9 MiB**，关闭后仍约 176–222 MiB；页面对象可释放不等于全部缓存归还 | 在大文档和低内存设备上明确总内存口径、警告/回收及长期使用；不能将独立 WebKit/GPU 数字简单相加为应用总量，也不能直接断定泄漏 |
| I05 | 兼容及设备覆盖 / 发布前 | 已有 iPhone 15 Pro Max 真机结果，但复杂真实文档、更多加密算法、低端设备与数小时使用未覆盖 | 在支持范围内扩大样本/设备；保留失败与复核记录，不把既有短时 30 次切书等同长期日常使用 |

已有 iOS 证据：[普通功能与模拟器](0.13.0-ios-validation.md)、[真机与裁边](0.13.0-ios-device-validation.md)。102 项普通单元、22 个不同 UI 用例为先前分批验证；裁边另有 12 项文档单元 + 2 项 UI 真机通过记录。六类大文档共 18 轮、30 次切书已做，不能再次列为“完全未测试”。

## 有差异，但尚未构成必须补齐的功能

| 项目 | 当前差异 / 边界 | 处理方式 |
|---|---|---|
| iOS PDF 左右裁边 | iOS 已实现，Android 没有；仅显示处理、全局内存、不保存 | 若需要 Android 再明确承诺；不为了统一界面自动传播 |
| 导入方式 | Android TXT 批量最多 20 本、新格式最多 5 本；iOS 单本 | 是否统一批量与重复策略需产品决定，现有单本导入满足基本能力 |
| PDF 阅读导航 | Android 独立页渲染，iOS 连续滚动 | 是客户端实现差异，不要求相同布局/手势 |
| TXT 进度选择 | Android 一位小数滑块；iOS 两位小数双滚轮 + 前往 | iOS 双滚轮已经明确保留，不作为缺漏 |
| PDF 大纲、页标签、高级文档内链接 | 当前没有完整专用入口，且未确认为 0.13 必交付 | 需要时单独决定；EPUB 有效内置目录已经属于基本范围，不能混淆 |
| OCR、批注、高亮笔记、编辑/签名/表单、EPUB 固定版式/DRM/媒体、新格式自动翻页 | 本版本未承诺；无文本层页面不可搜索/复制属于明确边界 | 不是本轮遗漏，纳入新版本前先做产品范围决定 |
| 云端书签、正文文件同步、记住 PDF 密码 | 当前不提供；进度同步不会上传这些数据 | 不因同步已实现自动新增承诺；记住密码须另评估安全存储 |

I01/I02 的既有业务规则缺口已修复；Android A01 与 iOS I03/I04 仍依据设备和预算处理，再完成 C01–C04。新增平台专属功能仍须单独确定范围，不自动传播。
