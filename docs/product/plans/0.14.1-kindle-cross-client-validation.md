# 0.14.1 Kindle 双端接续验证

日期：2026-10-25。用户已授权向既有 Android 任务发送接入及联调请求。公共 owner 在 Android 明确交接模拟器/已安装 APK 后执行；本记录是六原包、支持子集内的模拟器功能证据，不是真机性能、完整 G3 或生产部署声明。

## 环境与身份

- Android：0.13.1 / build115，`emulator-5554`，API35 / arm64 / 4 KiB。应用和 instrumentation 由 Android owner 构建、安装、交接；根编排不重装、不清数据。APK SHA-256：`fa82669a7fd8463f7b4742fa7c8fe721eaabfccee7719624c94358026aa0fb0b`。
- iOS：XLib Test iPhone / iOS26.5 / arm64 模拟器，原生 URLSession 与实际阅读模型、SQLite v5；根 `make test-ios`，关闭签名。结果包见下表。
- 同一轮临时 HTTPS 服务、一次性证书、独立 PostgreSQL17 集群；005 已应用，API 使用受限应用角色。账号只在本轮存在，两端使用不同设备 ID；不借用生产凭据或修改系统信任库。
- 原包：`kindle-mobi6.mobi`、`kindle-palmdoc.azw`、`kindle-huff.mobi`、`kindle-kf8.azw3`、`kindle-mixed.mobi`、`kindle-long.mobi`；原创 CC0，同字节身份，核心/profile 和正文映射共用。不是各自转换后的副本。

入口：`make test-kindle-cross-client-interop`。一次服务生命周期串行运行全部五阶段，任一阶段失败立即中断并停止临时服务/数据库，不绕过失败继续报成功。

## 失败与修复链

build114 首轮在 Android seed 阶段出现 `RejectedExecutionException`：关闭会话后，合并刷新仍可能向 Shutting down 的线程池提交任务。该轮没有进入 iOS 阶段，不算接续通过，日志 `artifacts/kindle-cross-client/failed-build114-20261025.log`。

Android owner 在本端将任务提交和 shutdown 置于同一生命周期锁，序列化刷新并在关闭后停止周期排队，增加可确定复现的关闭并发回归；293 项单元测试通过后交接 build115，再从第一阶段完整执行得到上表结果。没有修改公共正文语义、放宽后端校验或使用两个 iOS 会话替代 Android。

## 验收边界

六原包的 Node/JSC/Android 同源输出及两端真实接续已有证据，不能再写作 Kindle 尚无解析器/正文/契约或未做双向接续。双方的本地阅读、实际 DOM/图片、搜索、选文复制、书签及重排另有单元/UI 结果，见 [Kindle 实施记录](0.14.1-kindle-implementation.md)与 [Android 交付记录](../../../apps/android/docs/0.14.1-kindle-delivery.md)。
