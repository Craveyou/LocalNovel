# 0.13 大文档模拟性能测试

日期：2026-10-22。范围：Android/iOS 的 PDF、EPUB 原生模拟器流程。客户端继续使用 0.12.0；不作为真机性能或发布验收通过的证明。

## 样本和环境

样本由 [生成脚本](../../../scripts/document-performance.py) 创建，不使用私人书籍或第三方版权内容；大文件位于忽略目录 `artifacts/document-performance/fixtures`，SHA-256、大小及场景配置记录在同目录上级的 `manifest.json`。

| 场景 | 内容规模 | 原文件大小 |
|---|---|---:|
| pdf-small | 20 页、每页 32 行可搜索文本 | 8,995 B |
| pdf-large | 1,000 页、32,000 次关键词出现 | 440,028 B |
| pdf-images | 40 页独立 RGB/Flate 图片，无文本层 | 47,219,974 B（约 45 MiB） |
| epub-small | 2 章，每章约 4 KiB XHTML | 3,832 B |
| epub-large | 64 章，每章约 128 KiB XHTML，总正文资源约 8 MiB | 2,696,609 B |
| epub-long-chapter | 2 章，每章约 2 MiB XHTML | 1,318,050 B |

文本 PDF 高压缩率，因此“千页”压力与“大字节文件”压力分别由两类 PDF 覆盖。图片为确定性生成的噪声图，用于文件和图像解码压力，不代表实际扫描书籍的压缩、字体或视觉复杂度。EPUB 包含中文、emoji、组合字符、唯一段落 ID 及搜索词。

- 主机：Apple M2，8 个逻辑核心，16 GiB RAM。
- Android：专用 `xlib013-performance` AVD，API 35、arm64、2 GiB 配置、SwiftShader 软件图形，Debug build 84；清空的仅为该专用模拟器测试应用数据。
- iOS：XLib Test iPhone，iOS 26.5 Simulator、arm64、Debug build 65（最终根回归构建递增为 66）；每轮独立临时书库，原模拟器已有书库未清空。
- 每场景 3 轮；每轮导入、打开、10 次首尾单元跳转、搜索前后两批、全书无命中搜索、取消/替换搜索、关闭重开。EPUB 使用章内中点，验证目标文字在视口中，避免只验证保存坐标。
- 各平台的计时负载顺序运行；未清理操作系统磁盘缓存。重复轮次用于观察初始化与缓存差异，不冒充系统冷启动数据，不计算统计上不可靠的 P95。

## 测量口径

`import_ms` 包含原文件复制、格式校验和数据库发布。`open_ms` 从阅读会话打开到渲染器确认位置可用；Android 额外等待下一 UI 帧。iOS PDFKit 的确认不等于已测到首个屏幕像素，不将其写成“首像素绘制耗时”。导航以正式位置保存成功结束，轮询分辨率约 10 ms。

Android 内存为应用 PSS，iOS 为应用 physical footprint，50 ms 采样；都**不包含独立 WebView 渲染进程**，也不保证捕获瞬时绝对峰值。主线程指标为 20 ms 心跳的最大实际间隔，不能等同丢帧率或 Android ANR 判定。两种系统内存口径不直接作平台优劣比较。

原始结果还保留首批/第二批搜索、取消、重开、关闭后内存和每次导航耗时；批量搜索不改变正式位置与时间。图片 PDF 期望无文本搜索命中。iOS 的取消指标包含替换查询至新结果返回，Android 指标为取消请求至搜索任务退出，二者不直接横比。小样本可能在取消请求发出前已完成搜索，其取消数值不证明正在运行的任务可中断。

## 已修复的实测热点

1. **共享 Swift EPUB 解析反复扫描全文**：CPU 栈采样定位到 HTML 实体表循环替换，以及每个锚点反复计算累计正文 UTF-16 长度。改为缓存实体映射、单次匹配替换及增量锚点计数；补充实体不二次解码和 Unicode 回归。
   - 同一 64 章样本，优化前首轮导入 23.23 s、打开 25.58 s；优化后独立三轮导入约 2.7 s、打开约 3.6 s。
   - 优化前记录为诊断基线，后续重复测量主动停止以修复热点，不计作通过的完整测试轮次。
2. **超长章节全量排版**：双端对超过 262,144 UTF-16 单元的章节启用屏幕外直接子段落延迟排版；定位时先使目标段落进入视口，再定位字符。完整正文 DOM、选文与跨端 UTF-16 坐标保持不变；不支持该 CSS 的 WebView 继续常规排版。
   - iOS 首轮单章约 2 MiB 样本，原跳转约 4.8 s、打开 7.18 s；优化后跳转约 3.0 s、打开约 3.6 s。仍存在明显等待，不能宣称超长章节体验已达到真机发布标准。
3. **iOS PDF 全书搜索临时对象作用域**：对每页 PDFKit 文本提取增加局部 autorelease pool，限制异步连续扫描中临时排版对象的生存期。内存重复测量单列，不将系统缓存高水位直接判为内存泄漏，也不以未崩溃替代内存验收。

### 仍需处理的性能风险

- Android 千页 PDF 的全书无命中搜索约 **9.5 s**。首批结果和主动取消有独立测量，不能用首批较快掩盖完整扫描时延。
- iOS 超长章节定位仍约 **3.0 s**，延迟排版优化后仍需进一步缩小定位与布局工作量。
- Android 第一次 WebView 初始化所在的小 EPUB 场景，主线程心跳最大间隔 **1401 ms**；当前是模拟器软件图形环境，需真机复核启动卡顿。
- iOS 千页 PDF 应用采样峰值约 **319 MiB**。关闭后等待最多 5 s，三轮应用占用约为 182 / 190 / 200 MiB；首轮弱引用约 3.65 s 后释放，后两轮在等待期限内仍未全部释放。PDFKit 异步渲染和缓存需要更长时间及真机内存图确认，目前不据此下“已泄漏”或“已解决”的结论。

没有预先批准的数值性能预算，因此本轮结果是模拟测量与功能断言通过，**不标记性能验收通过**。

### 回归证据

## 复跑

```sh
python3 scripts/document-performance.py generate

# 必须是专用 xlib013-performance AVD；脚本拒绝其他 AVD，避免清空用户数据。
XLIB_ANDROID_SIMULATOR_SERIAL=emulator-5554 \
  sh scripts/test-document-android-simulator.sh

# 指向已启动的测试 iOS Simulator；测试书库使用独立临时目录。
XLIB_IOS_SIMULATOR_ID=<测试模拟器UDID> \
  sh scripts/test-document-ios-simulator.sh
```

大样本只以显式 Gradle 属性添加到 Android **测试 APK**；不会进入应用 APK 或常规单元测试。iOS 测试以 `XLIB_DOCUMENT_PERF_FIXTURES` 显式启用；未配置时跳过。可用 `XLIB_DOCUMENT_PERF_RUNS=1..10` 调整重复次数。脚本先调用对应根构建入口，按规则递增客户端 build，再运行模拟测试。

## 剩余验收

本轮是模拟环境基线与问题修复。真实扫描/复杂字体/更多加密样本、低端设备及真机峰值内存、WebView 子进程与 GPU 总开销、首个屏幕像素、长时间读书/反复切书及明确性能预算仍待验证。TXT 原有单元/功能回归保留；本报告不替代既有 P8 真机 TXT 性能任务。保持 0.12.0，后续按真实设备证据决定限额与 P7 收口。
