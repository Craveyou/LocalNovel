# PDF / EPUB 阅读需求与交付范围

## 当前结论

本文件仍限定 0.13 的 PDF/EPUB 范围。下一版本的 CBZ/CBR 与无 DRM MOBI/AZW/AZW3 单独见 [0.14.1 需求分析](plans/0.14.1.md)及[技术设计](../architecture/0.14.1-ebook-formats.md)，不追溯加入 0.13，不表示现有 v2 已接受新格式。

用户已确认 **Android 先行、先做 PDF，再做 EPUB；Android 验证后实施 iOS**。PDF 密码输入，以及 PDF/EPUB 的搜索、用户书签、正文复制和阅读进度同步均纳入 [0.13.0](plans/0.13.0.md)。开发期间客户端保持 0.12.0，完成对应客户端全部需求并验收后才升级。本文件是需求，不是已实现或已发布的证明；当前实现与测试证据见 [开发验证记录](plans/0.13.0-validation.md)。

[CAP-PDF-READING](capabilities/pdf-reading.md)、[CAP-EPUB-READING](capabilities/epub-reading.md) 为 active；双端已实现当前支持子集。iOS 大文档真机测量与连续切书已有[实际证据](plans/0.13.0-ios-device-validation.md)，复杂真实文件、低端设备与完整性能预算验收仍未完成，能力状态保留 partial。搜索、书签和同步扩展已有能力；[CAP-TEXT-COPY](capabilities/text-copy.md) 根据用户明确交付承诺提升为 active Shared Optional Capability，见 [Decision 0017](decisions/0017-multi-format-release-scope.md)。密码输入属于 PDF 阅读流程，不另建 Capability 或平台 Feature。

## 已确认交付范围

| 范围 | PDF | EPUB |
|---|---|---|
| 文件来源 | 本地导入，保留原文件 | 本地导入，保留原包 |
| 基本阅读 | 保留原版面、页面导航/跳页、缩放与适配；支持文本 PDF 和扫描件 | 按出版物阅读顺序跨章阅读、有效内置目录、文本/图片与可重排正文 |
| 本地恢复 | 文档页面及必要页内位置 | 正文资源及内容锚点；排版变化后保持内容位置 |
| 密码 | 需要打开密码时提示输入；正确后继续打开，错误可重试，取消不损坏数据 | 不因 PDF 密码需求承诺 EPUB DRM 解锁 |
| 搜索 | 在可提取文本中搜索并定位到原页面，扫描件无文本层时明确提示不可搜索 | 在支持的正文文本中搜索并定位到内容锚点 |
| 用户书签 | 添加、列出、跳转、单条删除和同位置判重 | 添加、列出、跳转、单条删除和同位置判重，重排后仍定位原内容 |
| 正文复制 | 用户主动选择并复制允许提取的原文 | 用户主动选择并复制支持的正文文本 |
| 跨设备进度 | 同一源文件的页面/页内定位，遵循既有阅读前比较和时间优先规则 | 同一源文件的内容锚点，跨端重排不依赖屏幕页号 |
| 外观 | 应用界面跟随主题，文档版面和图片不强制反色 | 可重排正文的可读字体/字号、行距与明暗外观，具体样式覆盖以样本验证 |

同步仍为可选的**阅读进度同步**：不上传文件、正文、标题、路径、书签、搜索结果、选区、密码或阅读偏好；不扩展成书库或书签云同步。两个设备均需自行导入相同原文件，密码文档分别解锁，不跨设备保存或传递密码。

扫描件可以阅读、添加书签和同步位置；无文本层时搜索和复制明确不可用，不自动执行 OCR。文档禁止文本提取或引擎不能可靠提供文本时，说明受限原因，保留阅读和其他可用功能，不绕过保护。普通文本 PDF 与受支持 EPUB 的搜索/复制必须有成功样本，不能以受限提示代替全部实现。

自动翻页的新格式覆盖、PDF OCR/批注/编辑/签名/表单/附件/脚本、EPUB 固定版式/媒体/DRM 等不因本次决定自动纳入；其余待决范围见末表。具体格式版本和支持子集需要兼容样本验证，不承诺完整标准覆盖。EPUB 阅读顺序及可重排/固定版式的参考见 [W3C 阅读系统规范](https://www.w3.org/TR/2024/REC-epub-rs-33-20241017/)。

## 共同用户流程

1. 本地选择文件，识别实际格式，校验基本结构；仅改后缀不能变成其他格式。原始加密 PDF 仍是原文件，不以解密重写后的副本替代身份。
2. 原文件的应用管理副本与书库记录一致发布，保留用户源文件。导入失败/取消清理本次临时数据，不产生可点击的坏书籍。有效的待密码文档可保留为“需要密码”，不能误标损坏或写入虚假页数/进度。
3. 混合书架展示 TXT/PDF/EPUB，沿用 metadata 编辑、删除确认和本地/云端删除隔离。跨格式同名不等于重复内容，TXT 的 20 本批量上限不自动传播。
4. 打开 PDF 若需要密码，先完成下述解锁。已有阅读位置和时间保持不动；未解锁不能开始进度比较、上传或正式阅读。
5. 文档可定位后恢复本地位置；启用同步时先拉取并比较双方进度，提示当前进度和远端目标，用户决定并完成定位后才进入正式阅读。首次无有效位置从起点开始，不生成伪阅读时间。
6. 实际正式位置改变才记录阅读时间。搜索预览、密码输入、恢复、重排和单纯缩放不修改正式进度或时间。退出/重启恢复最后有效位置，失败不写成空书或 0% 成功。
7. 本地删除清理本书结构化数据和派生缓存，按既有机制重试文件删除；不删除用户源文件或云端进度。云端仍只允许单书进度删除，成功后暂停本次阅读会话上传。

## PDF 密码流程

- 首次打开或重开需要密码的文档时提示输入，区分“需要密码”“密码错误”“格式/加密方式不支持”“文件损坏”；错误提示不能泄漏密码。
- 正确密码在能打开文档且定位有效后继续阅读前流程；错误可在同一流程重试，不重建书籍、不清空旧进度；取消返回原入口，保留已成功导入的原文件和旧状态。
- 密码默认只在当前文档打开会话内存中使用，关闭或取消后释放，不自动记住。不得写入普通 SQLite、设置、缓存、日志、错误报告或同步请求。以后如需“记住密码”，须另行确认并使用平台安全存储。
- 不生成持久化解密正文副本；敏感派生缓存不得包含密码或未受保护的解密正文、文本索引和页面内容，具体临时资源清理方式在工程方案中验证。
- 支持的常见打开密码加密方式需以真实样本明确；不能把所有密码 PDF 拒绝来满足此需求，也不承诺破解密码、解除权限或支持全部加密算法。

## 格式位置语义

| 格式 | 持久化位置真值 | 派生展示 | 不能采用的替代 |
|---|---|---|---|
| TXT | 现有原文件绝对字节 offset | offset/fileSize 百分比、客户端分页 | 字符索引或屏幕页号 |
| PDF | 绑定源文档的页面定位及必要页内锚点 | 页码/总页数、阅读进度百分比 | PDF 二进制 byte offset、仅缩放倍率 |
| EPUB | 绑定源文档的正文资源及内容锚点 | 章节、客户端分页、全书进度百分比 | 压缩包 byte offset、排版后的全书页号 |

原文件 SHA-256 + fileSize 继续作为文件身份；格式与定位版本用来解释位置，不以书名判定同一本。PDF 对外页码从 1 开始，内部索引及页标签须明确定义映射；页内锚点须独立于屏幕尺寸和缩放。EPUB 资源/锚点编码须跨平台可解析。定位规范、同位置规范化、百分比算法与失效处理在实现前固化到共享 Contract，不在此预造 SQL 或 HTTP 字段。

搜索命中、书签和正式进度使用同一格式定位语义，但分离持久化/临时状态；不将搜索预览写成进度。书签按同书的规范化位置判重，不按百分比、客户端分页或摘要判重。改变字号、方向、缓存或渲染引擎不能丢失正式位置；不同源文件不得静默套用旧锚点。PDF 有效页内平移及 EPUB 内部链接/脚注导航作为正式阅读位移；搜索预览保持临时状态，详见验证记录。

## 存储、API 与兼容性

以下要求已用于双端 schema 3、OpenAPI v2 和 Backend 迁移 003 的实现；具体兼容边界与测试状态见开发验证记录：

- SQLite 保持结构化业务与非敏感设置的单一持久化源；Book 增加格式语义，Progress/Bookmark 支持类型化定位和版本。业务通过 Repository/LocalDatabase 访问，不增加 JSON、Preferences 或 UserDefaults 业务存储。
- 原始文档留在文件系统；非敏感的解包、渲染、缩略图和搜索索引为可重建缓存，不成为正式位置的第二数据源；密码 PDF 另遵守上文敏感缓存边界。Token/Secret 保持平台安全存储。
- Schema 迁移保留所有 TXT 书籍、字节位置、时间、书签、目录、设置与同步状态；旧记录明确映射为 TXT，可重复、原子失败，不清空数据库重建。
- 多格式同步已同步更新 [Local Storage Contract](../architecture/local-storage-contract.md)、[OpenAPI](../../contracts/openapi.yaml)、[API 文档](../API.md)、Backend PostgreSQL 迁移/校验/裁决、双端实现和兼容性测试。后续修改仍需保持这些契约一致；Backend 保持 PostgreSQL。
- TXT v1 无格式和定位版本，不能把 PDF 页号或 EPUB 锚点伪装成 offset，不能以文件大小乘百分比伪造定位，不能混入现有 TXT 远端缓存。已实现的 v2 协议表达格式、定位版本、可互操作的位置和用于提示的进度语义；路由和字段以 OpenAPI 为准。
- 保留旧 TXT v1 的行为与可读写兼容性。未知格式、未知定位版本、无效/越界锚点应明确拒绝或标示不可应用，客户端保留本地状态，不静默按 0% 或其他格式定位。旧客户端不得读到无法解释的新格式状态；能力协商/协议隔离方案必须先明确。
- 仍按真实阅读时间优先、阅读前比较并由用户确认、仅活动书籍上传、离线结束不补传、单书云端删除后暂停本次会话。失败继续可用的本地阅读，不跳页、不刷新时间。
- 文档不自动执行脚本、附件或获取远端资源；外部链接由用户主动操作。包路径、解包限额、取消和资源隔离在工程方案落实。

## 渐进交付与验收

1. **契约准备**：固化格式位置、密码状态、支持样本、本地迁移和多格式同步协议/兼容策略；保留现行 TXT 行为。
2. **Android PDF**：先完成导入、阅读/解锁、恢复，再完成搜索、书签、复制和同步；全部范围验收后进入 EPUB。协议与 Backend 是同步交付依赖，不能留到版本升级后。
3. **Android EPUB**：完成基本阅读、目录、重排定位与四项增强能力；混合书库和 TXT 回归通过，记录样本及业务结论。
4. **iOS 后续**：Android 验证后按 PDF → EPUB 实现相同业务语义，各端 UI/渲染可以不同。现有 TXT 双滚轮决定保持，不自动规定新格式控件。
5. 各客户端完成全部对应需求、跨端接续与验收后才升 0.13.0；中途用 0.12.0 测试，不发布半成品能力状态。

| 验收类别 | 最低验证内容 |
|---|---|
| PDF | 文本/扫描、多页/单页、中英文、旋转/不同尺寸、缩放、跳页边界和重开恢复；损坏文档保留旧状态 |
| PDF 密码 | 正确/错误/重试/取消/重开、保留旧位置和时间、未解锁不比较/上传、密码不落库/日志/云端、无解密缓存残留、不支持加密明确提示 |
| EPUB | 阅读顺序与文件名乱序、跨章、有效/缺失目录、组合字符、图片、排版变化后恢复；损坏/缺资源/受限内容明确处理 |
| 搜索 | 大小写不敏感、不重叠、2–32 字素簇、200 条分批、用户主动回绕、原页/锚点定位、搜索临时状态隔离；无文本层/禁止提取明确提示 |
| 书签与复制 | 同位置去重、单条删除、恢复/重排/缓存清除后跳转；文本选择/取消/复制保留原文及换行，不加书名位置、不修改正式进度 |
| 同步与云端删除 | 同文件双端 PDF/EPUB 接续、两端分别解锁、提示双方百分比、回读的较新时间优先、接受/拒绝跳转、离线恢复/退出、仅活动书上传、单书删除暂停、旧 TXT 客户端兼容；不同文件和无效定位不串用 |
| 文件与数据 | 同名不同内容、失败/取消/中断、空间不足、文件删除重试、迁移幂等、缓存清除不丢业务数据 |
| 回归与性能 | TXT 导入/阅读/搜索/书签/目录/偏好/同步不回退；选定小/大样本测导入、首屏、搜索、导航和内存，不预造性能数字 |

## 支持边界与后续验收

已确定的 PDF 优先、密码输入、搜索/书签/复制/同步不再列为可选待决项。当前实现采用的具体边界见开发验证记录；仍需在版本验收时复核：

| 问题 | 当前状态 |
|---|---|
| 格式兼容子集 | 已实现普通文本/页面与打开密码 PDF、无 DRM 可重排 EPUB 2/3 子集；复杂文档和更多加密样本待验证 |
| 高级功能 | PDF OCR/批注/编辑/签名/表单、EPUB 固定版式/媒体/DRM、新格式自动翻页未纳入本次明确承诺，需另行范围决定 |
| 导航与阅读事件 | PDF 大纲/高级内链接未设专门入口；页内平移、EPUB 正文链接/脚注导航作为正式位移，搜索为临时状态 |
| 限额与进度规范 | 限额与 v1 locator 编码已实现并有共享向量；限额尚需真机性能数据复核 |
